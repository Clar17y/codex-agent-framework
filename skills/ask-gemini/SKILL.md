Use the shared framework at `{{CODEX_ROOT}}/agent-framework`. For a normal task, run `provider_runner.py status --activity ACTIVITY --config ROUTING`, then `provider_runner.py dispatch --activity ACTIVITY --workspace WORKSPACE --task-file TASK --config ROUTING`. To explicitly choose Gemini, add `--provider gemini`; this selects the first eligible Gemini profile in that activity. The default implementation chain starts with Gemini 4 Hydrogen medium (`gemini-hydrogen`), followed immediately by Gemini 3.8 Flash medium (`gemini-flash`) as safe fallback. The framework conservatively accounts for Hydrogen and Flash together in `gemini-quota.json`; a cached or confirmed quota limit blocks both profiles and advances to subsequent providers rather than retrying Flash. A settled terminal model-unavailable error on Hydrogen safely falls through to Flash, while unresolved writer claims, timeouts, or pending executions prevent fallback. Routing version 14 upgrades untouched prior packaged implementation chains to promote Hydrogen ahead of Flash only when the previous Flash routine selection is uncustomized; existing custom chains, customized Flash or Hydrogen profiles, and legacy provider pins are preserved. Keep the task contract, ownership, Jev evidence, quota cache and pending state intact. Gemini static activities require the installed validated `framework-reader` custom agent; plan mode alone does not restrict writes or commands.

The legacy `implement --provider gemini` entry point remains pinned to Flash medium (`gemini-3.8-flash-medium`) and retains its historical native Luna fallback semantics. Use it only when explicitly preserving an old workflow. Normal activity dispatch uses the new Hydrogen profile. A blocked writer claim must be resolved before any overlapping fallback.
