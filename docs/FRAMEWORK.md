# Framework operation

Version 15 keeps one installed `routing.json` under the Codex home. `profiles` name a provider, CLI model and effort; `activities` list profiles in priority order. Provider entries supply executable, timing and secret controls. Profiles override model and effort without mutating their provider entry. The packaged defaults cover 16 activities and four subscription providers, plus opt-in Inception exploration; operators may edit chains and profiles. Malformed, duplicate, unknown or disabled references fail before model execution.

## Bounded task

The task file is JSON with `objective`, `acceptance_criteria`, `owned_paths`, `validation` and `instructions_files`. Writing activities require nonempty explicit `owned_paths`; a directory claim includes descendants. The optional `review.author_provider` moves that provider behind other eligible providers for independent review. Add `review.candidate`, `review.diff_path`, `review.base` and `jev.review` evidence for a stable reviewed candidate. With `workflow.require_jev_evidence=true`, implementation contracts include `jev.search` and review contracts include `jev.review`; attempted review evidence must match the saved diff SHA-256. Coverage maps identify planned, proved and unproved cases with candidate-specific evidence or limitations.

```powershell
$framework = "$HOME/.codex/agent-framework"
$runner = "$framework/scripts/provider_runner.py"
python $runner status --activity implementation --config "$framework/routing.json"
python $runner dispatch --activity implementation --workspace "C:/repo" --task-file "C:/repo/.llm-output/task.json" --config "$framework/routing.json"
python $runner dispatch --activity independent_review --workspace "C:/repo" --task-file "C:/repo/.llm-output/review-task.json" --review-reason "optional for medium; required for high/deep" --config "$framework/routing.json"
```

`--profile` pins a profile; `--provider` restricts selection to the first eligible profile on that provider. They cannot be combined. `--dry-run` makes no inference. `status --activity` reads local quota files only. `quota-set --provider openai|claude|gemini|muse|inception --reason TEXT [--reset-at ISO_TIME]` records a user-reported account limit without contacting the provider. Never invent a reset time, redeem credits or bypass a cache with another state directory.

Muse defaults to its existing CLI/stored authentication. The framework strips process API-key overrides on that route and does not inspect stored credentials, so it cannot determine whether stored auth is a subscription or API billing. To explicitly use a selected Meta Model API key and its available credits, add `--provider muse --muse-auth api` to status, activity dispatch, legacy implement or quota-set. The option requires that provider selection and cannot combine with `--profile` or legacy Claude review. It does not change routing defaults or enable automatic API spending fallback. [Meta limits Wonder Full to subscriptions](https://dev.meta.ai/docs/models); in API mode, a configured `muse-wonder-full-1.0` or `cli-default` is replaced with `muse-wonder-1.0`, retaining the selected effort. Status, run results and quota metadata report the effective model, and duplicate API routes with the same model and effort are attempted only once. Other configured models remain unchanged; the option does not establish entitlement.

Set `META_API_KEY` in the parent environment through a secret manager or secure shell setup. On Windows, the runner also reads the persisted User environment if the process variable is absent; an explicitly blank process variable fails closed. A real API-mode launch requires a nonempty key and supplies it through the Muse Code child's environment; that process's own subprocesses can inherit it. It never stores the selected key, modifies Muse's stored login, or passes it in argv, task files or routing JSON. Known Muse key names and configured custom key names stay filtered from other providers, default Muse children and framework helper processes, and their process and User values are redacted from artifacts. To avoid corrupting task text or protocol fields during redaction, configured secrets shorter than eight characters or overlapping framework control labels, and task text containing a protected secret, are rejected before launch. Local status, quota-set and dry-run do not require a key or contact Meta.

```text
python ~/.codex/agent-framework/scripts/provider_runner.py status --activity implementation --provider muse --muse-auth api --config ~/.codex/agent-framework/routing.json
python ~/.codex/agent-framework/scripts/provider_runner.py dispatch --activity implementation --provider muse --muse-auth api --workspace /absolute/repo --task-file /absolute/task.json --config ~/.codex/agent-framework/routing.json
python ~/.codex/agent-framework/scripts/provider_runner.py implement --provider muse --muse-auth api --muse-profile complex --workspace /absolute/repo --task-file /absolute/task.json --config ~/.codex/agent-framework/routing.json
python ~/.codex/agent-framework/scripts/provider_runner.py quota-set --provider muse --muse-auth api --reason "User-reported API limit" --config ~/.codex/agent-framework/routing.json
```

Use platform-appropriate paths. Meta documents environment-key precedence in [authentication and billing](https://dev.meta.ai/docs/muse-code/auth) and additional-key PAYG billing in [subscriptions](https://dev.meta.ai/docs/muse-code/subscriptions). Meta may charge pay-as-you-go once credits are gone. This framework does not independently check balances or enforce a credit ceiling; explicit API mode authorizes that billing route, not a guaranteed credit-only cap.

Stored-auth Muse limits retain `muse-quota.json`; explicit API limits use `muse-api-quota.json`. Status, dispatcher preflight, execution recheck, recording and manual quota-set use only the selected mode's cache. Corrupt state blocks that mode, and recording never shortens an active longer block. Model profiles share a cache within each mode, and switching modes never clears existing evidence. Automatic recording recognizes specific CLI limit diagnostics; actual API credit-exhaustion wording has not been verified and may not be cached. Both modes retain the same writer/pending inventory, overlap checks and process cessation protections. Results expose non-secret `muse_auth` (`stored` or `api`) and the selected `quota_path`; `stored` makes no claim about the saved credential's billing type.

## Capabilities and failure handling

Planning, exploration, test design, independent/security/deep review, refactor audit and docs research are static readers. Implementation, complex/long-horizon implementation, testing, verification and documentation are writers. Verification may run checks and write generated/scratch files within its task; source edits still follow the contract. `orchestration` requires `allow_delegation: true`, holds a claim on its declared paths, and must call this dispatcher for children. Registered children may work inside that parent scope; unrelated overlapping writers cannot.

Codex runs `codex exec` with a pinned OpenAI model/effort, forced ChatGPT login, the OpenAI provider, ignored user config and an ephemeral session. Windows accepts `mxc`, `elevated` or `unelevated`. Normal activities use `providers.openai.windows_sandbox` (default `mxc`); orchestration uses `providers.openai.orchestration_windows_sandbox` (default `unelevated`). Current-host MXC blocks Python strict path resolution needed by the child dispatcher, consistent with the [reported Windows issue](https://github.com/openai/codex/issues/53045). The supported compatibility mode preserves strict canonical ownership checks; local controls proved state-root writes and denied an outside-root write. Operators can choose another supported mode for their host. Its read-only sandbox and per-run apps/agents/plugins/MCP controls restrict static roles. OpenAI children retain `CODEX_HOME` for subscription auth but discard inherited desktop IPC, policy and task-session variables; those can inject host MCP tools or reject local reads. Claude static roles expose only Read/Glob/Grep with strict MCP config. Muse static roles request a per-run `read_file` toolset and disable shell, workspace writes and web tools; this narrows file discovery compared with the other readers. First-party Muse documentation says toolset selections limit the main conversation, an offline invalid-tool control is rejected before execution, and a bounded current-host transport probe offered only `read_file`. Managed-policy conflicts remain untested. Gemini static roles require the installed `framework-reader` custom agent with only `view_file` and `grep_search`; the dispatcher validates its global file path and rejects duplicate YAML names in known global, project and plugin locations before launch. A signed-in probe selected that named agent and completed actual fixture reads; its initialization tool catalog also lists tools outside the selected agent, so that catalog is not evidence of their availability to this reader. Gemini `--mode plan` only prepends a prompt and is insufficient as a permission boundary. Inception exploration runs an opt-in read-only subprocess adapter (`scripts/mercury_provider.py`) with model `mercury-3`, low reasoning effort, temperature 1, and the `mercury-explorer` profile. The adapter connects exclusively to the fixed HTTPS endpoint `https://api.inceptionlabs.ai/v1/chat/completions` with redirects rejected, and allows only root-confined reader tools (`list_files`, `search`, `read_file` via `scripts/mercury_reader.py`); shell, writes, web, delegation, and environment tools are omitted. Confinement excludes `.git`, `.llm-output`, `output`, `vendor`, `.worktrees`, and `node_modules`, and blocks symlink/reparse/hardlink escape, credential files, and binary files. Retrieved text is treated as untrusted, and exploration answers require citations in findings evidence. Resource budgets enforce a monotonic 180s deadline, max 48 turns, max 40 tool calls, 8192 per-call and 48000 aggregate completion tokens, with outgoing requests capped by remaining budget. Hidden reasoning deltas are discarded. Inception only accepts the `exploration` activity; all other activities and legacy commands fail before launch. `INCEPTION_API_KEY` is retrieved strictly from the process environment or Windows User registry, filtered from all other provider children, and redacted from artifacts. Transient 429 rate limits are distinguished from confirmed account quota exhaustion; transient 429 responses do not poison the quota cache.

Mercury forwards sanitized automatic `AGENTS.md`/`CLAUDE.md` and selected task instruction-file content from the runner wrapper, together with the complete task contract including scope and validation, into the model request; it does not execute those instructions locally. Before range selection or search matching, its reader filters recognized credential assignments whose values begin on following lines, form indented plain scalars or mappings, continue inside ordinary or triple quotes (including YAML doubled-apostrophe escapes and language-prefixed adjacent or explicitly continued literals), use YAML block scalars, or span balanced arrays, objects and parentheses. Compound values retain at most 64 nested delimiters and share existing scan limits. Plain credential values remain suppressed across blank/comment lines until a sibling field or structural/document boundary at the key's indentation; URL and colon/equals-bearing value text do not terminate them. Line numbers remain stable. This filtering does not detect arbitrary encoded or obfuscated credentials.

For Mercury, a relative `providers.inception.adapter` is resolved from the framework root (the parent of the runner's `scripts` directory), so `scripts/mercury_provider.py` names the installed script. The adapter has a 180-second absolute deadline; the example runner grants an additional 10 seconds to receive and persist its terminal. HTTP headers, SSE chunks, and every reader call share that deadline. Each reader also has a 15-second local deadline, 10,000 directory entries, 16 MiB scanned bytes, 100,000 scanned lines, a 2 MiB per-file ceiling, and 32 KiB per-line ceiling. Traversal prunes unrelated subtrees before enumeration when prefix or glob scoping allows it. Listing stops at 150 paths; search stops at its match/character ceiling; reads stop at their range/output ceiling. Truncated totals are unknown rather than obtained by scanning the remaining corpus. Exceeding a work ceiling fails the run coherently.

SSE responses are limited to 1 MiB, 10,000 data events, 128 KiB per event/line, and 32 KiB per tool's arguments; error bodies are limited to 8 KiB. Malformed chunks, invalid or absent usage, contradictory finish/tool states, events after finish, missing DONE, and data after DONE fail before executing tools. Completion usage must be a nonnegative integer within the request's remaining allowance. A completed result requires validated citation JSON and exit 0; ordinary local failures use exit 1 and confirmed quota exhaustion exit 20. Unknown or contradictory terminals and abnormal exits block fallback.

Outbound prompts and tool text, telemetry, and saved artifacts filter credential assignments, bearer/key patterns, and known framework secret values while preserving source line numbers. One-way value fingerprints let the isolated adapter filter known host credentials without receiving the host keys. Reader entrypoints reject all symlink/reparse paths and files with multiple hardlinks. On Windows, directory handles deny deletion while descendants are opened; on POSIX, directory-relative no-follow opens anchor traversal. Binary detection and text reads use the same validated file descriptor; Windows device paths, alternate data streams, and drive-relative paths are rejected before opening. This is a bounded text filter, not a guarantee of detecting arbitrary encoded or obfuscated credentials.

A terminal account quota result skips every model on that account until a known reset or bounded probe. Antigravity (`gemini`) narrows only an exact individual-quota diagnostic on a recognized CLI model ID to its Flash, Claude or Argon family. All effort variants share a family; Opus and Sonnet share Claude. Generic limits, unknown IDs (including Hydrogen), conflicting or ambiguous evidence and manual `quota-set` remain account-wide. Hydrogen has no separate framework quota family. An unknown requested model conservatively considers all cached Antigravity family evidence; a confirmed Hydrogen quota blocks Flash and every other Antigravity profile. A settled Hydrogen model error may advance to Flash only after writer ownership is resolved. Corrupt account or family state fails closed. Status, dispatch preflight, execution recheck and recording use the same scope rules. A settled family limit can advance immediately to a different Antigravity family; account authentication and provider disablement still block every route. Authentication, model, permission and transient 429 errors are distinct. The dispatcher attempts each route at most once. It advances after known terminal/setup failure and resolved writer ownership, carrying bounded prior logs/results and preserving partial files. A missing or malformed terminal, timeout or cancellation retains the pending claim; inspect and resolve it only after authoritative cessation. Disjoint claims can proceed under the shared lock. No live fallback is launched from an uncertain writer.

Standard Codex independent review starts with `agy-opus` (Claude Opus 5.5 medium via Antigravity), then `gemini-argon` (Argon medium), followed by direct Claude, OpenAI and Muse alternatives. Both Antigravity profiles are provider `gemini`, so author-provider diversity treats them together. Review prefers a different provider from the author and reports when only the author's provider succeeds. The saved candidate and Jev diff binding remain the same across retries. Model completion alone does not establish acceptance; the primary assesses test evidence and unresolved findings. High/deep review requires `--review-reason`.

## Standalone CLI orchestration

Launch the chosen CLI agent with a task whose `activity` is `orchestration`, `allow_delegation` is true, and whose instructions give the installed runner/config paths above. The CLI agent should scope work, write child contracts under its workspace `.llm-output`, call `dispatch --activity ...` for each child, wait for result JSON and command checks, then integrate and review the candidate. It must obey nonoverlapping ownership and stop on unresolved child claims. For OpenAI orchestration, `codex exec` stays in workspace-write mode with the canonical shared state as an additional writable root and network enabled for authenticated child CLI calls. Set `providers.openai.orchestration_writable_roots` only to concrete provider cache directories that a child needs; filesystem/home roots are rejected. This is agent-directed orchestration through the shared dispatcher, not a self-operating scheduler. Plain planning does not execute that flow.

The legacy `implement` and `review` commands retain pinned Gemini/Muse and Claude behavior for compatibility. They reject `--activity` and `--profile`; use `dispatch` to avoid a write-capable activity with a legacy read-only ownership role. Legacy native fallback metadata is separate from the activity chains. Run the isolated offline CI entrypoint `python scripts/run_tests.py` after runner or installer changes. Fake CLI tests do not prove subscription entitlement or live permission behavior.

## Installation and state recovery

The default installation root is `~/.codex`; `CODEX_HOME` or `install.py --codex-home` selects another. The Gemini reader helper always lives under the actual user home at `~/.gemini/config/agents/framework-reader.md`, independent of the Codex installation root. The installer backs up files it owns before replacement, merges its marked policy block, and records hashes in `install-manifest.json`. An ordinary v15 upgrade adds missing profiles and integrates exact v12, accumulated v13 and Hydrogen v14 packaged chains only when their old and replacement profiles have no saved customizations. Routine implementation starts with Hydrogen medium then Flash medium; legacy Gemini implement remains pinned to Flash. Both Codex and Claude host chains are recognized. Missing chains with relevant custom selections retain preceding routes rather than activating newly introduced custom or disabled profiles. v15 and future-version saved chains are not migrated again. Custom chains, profiles and other settings remain authoritative. It preserves quota bytes and corrects the reader path generated by an earlier custom-root install. `--refresh-routing` is an explicit rebuild for moved executables and can discard retired custom secret-name metadata; inspect that choice before using it. The Gemini reader helper upgrades only when its installed bytes match the previous manifest hash; an operator edit or unowned collision stops installation before overwrite. Start a new Codex task to discover installed roles and skills; an already loaded host catalog does not switch models dynamically.

Use the installed `routing.json` and its sibling `state/` for every workspace. `--state-dir` is for deliberately shared alternative state or isolated offline fixtures, never to evade a cached account block. A standalone orchestrator passes its effective state directory and run ID into each child dispatch. Account files include `openai-quota.json`, `claude-quota.json`, `gemini-quota.json`, `muse-quota.json`, and `inception-quota.json`. Antigravity family records use `gemini-flash-quota.json`, `gemini-claude-quota.json` and `gemini-argon-quota.json`. A recognizable individual limit in legacy `gemini-quota.json` blocks only its family without rewriting that file; a new account limit then goes into `gemini-account-quota.json`. Account and family evidence coexist under the quota lock and the latest applicable retry wins. Expired evidence permits a probe without deletion. Direct Claude subscription state remains independent from Antigravity Claude. DeepSeek has been removed; a leftover `deepseek-balance.json` is ignored and can be deleted. A confirmed terminal limit records observation, retry time and source evidence. A precise provider reset is used when unambiguous; otherwise `quota_probe_seconds` is only a bounded probe cooldown. Local `status` means eligible to try, not authenticated, entitled or guaranteed available.

Per-run logs, task prompt, redacted result and git evidence live under the active workspace's `.llm-output/agent-framework/`. `stdout.log` can still contain sensitive model or tool material and should be handled accordingly. Stream progress in `progress.json` and quiet-period `heartbeat.json` is diagnostic liveness, not proof of completion. The runner reads bounded stream tails, requires provider-specific terminal records, and preserves partial edits. Do not delete scratch logs to force retry.

Writers record claims under `state/workspaces/<workspace-hash>/gemini-pending/<run-id>.json`; legacy markers are still inspected. An unresolved marker blocks exact, ancestor or descendant paths, while disjoint claims can proceed. A timeout can prove the local CLI exited without proving escaped descendants or provider-backend cessation. Inspect the `pending_path` in the result and confirm the prior session stopped before marking it `resolved`; never resolve it merely because another provider is available. Orchestrators keep separate run and child-dispatch records that also block overlapping unrelated writers. An unresolved child blocks parent settlement and replacement; child registration stops accepting launches once the parent finishes. After confirming a child with no provider pending path has stopped, run `provider_runner.py resolve-orchestration --state-dir STATE --workspace WORKSPACE --run-id ID --child-id CHILD_ID --confirm-stopped --reason TEXT`. Resolve any provider pending record first. After every child is settled, use the same command without `--child-id` to confirm an uncertain parent has stopped. The records retain the reason and timestamp. If a child JSON record is corrupt, recovery fails closed: preserve its original bytes separately, confirm every child process and provider session has ceased, then reconstruct that same child's minimal valid record with `status: unresolved`, the original `parent_run_id`, workspace and owned paths, plus its `provider_pending_path` if known. Resolve the provider pending record first, then use the explicit child and parent cessation commands; never delete the corrupt record to unblock work. A completed CLI message without a child dispatch is not successful orchestration.

Legacy direct routes still use their historical fallback metadata: Gemini exhausted or unavailable leads to native Luna medium; Claude review leads to native Astra low. The activity dispatcher instead walks its configured chain, returning `all_routes_unavailable` if no route completes. Exit 0 means a provider produced a validated terminal result; it does not establish test coverage or merge approval. Exit 20 indicates cached or newly confirmed quota fallback. Other failures report setup, permission, terminal or pending state explicitly. Authentication, model failures and transient 429 responses do not poison the quota cache. Review and integration should reuse matching check evidence and a stable candidate; provider output is a handoff, not independent verification.

Mercury treats explicit transient throughput diagnostics (including too many requests, token/request rates and concurrency limits) as rate limits even with a generic quota label. Adapter and runner use the same classification precedence; only confirmed account/balance exhaustion records the Inception account cache.
