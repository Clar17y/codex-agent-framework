# Multi-provider activity routing

This package routes bounded coding activities across OpenAI Codex CLI, Claude Code, Google Antigravity (`agy`) and Muse Code. The primary host model remains the user's selection. An explicitly chosen CLI agent can orchestrate by calling the same dispatcher for child tasks; the framework does not run a separate autonomous pipeline.

Install with `python install.py` (Python 3.11+). The additive v13 installer adds Antigravity Opus, Sonnet and Argon profiles and migrates only unchanged packaged default chains. It preserves saved provider executables, timing, custom model/profile/chain choices, quota state and credentials. It registers a narrowly named Antigravity reader agent and rejects a conflicting definition. Use `--dry-run` to inspect planned changes; actual signed-in provider access must be checked separately.

The canonical commands are:

```powershell
$framework = "$HOME/.codex/agent-framework"
python "$framework/scripts/provider_runner.py" status --activity implementation --config "$framework/routing.json"
python "$framework/scripts/provider_runner.py" dispatch --activity implementation --workspace "C:/path/to/repo" --task-file "C:/path/to/repo/.llm-output/task.json" --config "$framework/routing.json"
```

Choose from `orchestration`, `planning`, `exploration`, `implementation`, `implementation_complex`, `implementation_long_horizon`, `test_design`, `testing`, `verification`, `independent_review`, `security_review`, `refactor_audit`, `documentation`, `docs_research`, `deep_review`, and `structured_thinking`. `--profile NAME` pins one eligible profile, while `--provider NAME` selects the first eligible profile on that provider. `--dry-run` shows the selected command without inference. Activity chains and profiles live in `routing.json`.

The dispatcher shares account-wide quota evidence across activities and workspaces. Antigravity also isolates known Flash, Claude and Argon families when an exact individual-quota diagnostic establishes model scope; all effort variants share a family and Opus/Sonnet share Claude. Unknown or ambiguous limits and manual `quota-set` stay account-wide. Direct Claude subscription state remains separate. Standard Codex independent review starts with Antigravity Opus medium then Argon medium, while Flash stays first for economical routine work. Author-provider diversity can reorder review routes. It moves to the next route after a known terminal failure and resolved writer claim. Unknown completion, cancellation and timeout retain the pending claim, blocking overlapping work. An all-routes-unavailable result is not completion. File ownership and Jev evidence remain part of each task contract. See [FRAMEWORK.md](docs/FRAMEWORK.md) for details.

Static analysis activities (including advisory structured_thinking) use restricted read/search tools. Questions involving judgment or design choices select the structured-thinker protocol (inline for small judgments, dispatched via structured_thinking, or via the native structured-thinker role). Writing activities require explicit owned paths. A `verification` worker can execute checks and write generated/scratch artifacts within its contract. Independent review starts fresh against a saved candidate and Jev diff binding, and prefers a provider other than the author when one is eligible. High/deep review requires a concrete reason.

The legacy `implement`, `review`, `status --provider` and `quota-set` commands remain for existing scripts. Their pinned-provider fallback metadata does not define the new activity chains. DeepSeek has been removed. Upgrades drop it from `routing.json`, and its API key names stay filtered out of every provider process.

Muse also supports explicitly selected Meta Model API credits through Muse Code itself: set `META_API_KEY` securely in the parent environment (or persisted Windows User environment), then use `--provider muse --muse-auth api` with `status`, activity `dispatch`, legacy `implement` or `quota-set`. For example, `python ~/.codex/agent-framework/scripts/provider_runner.py status --activity implementation --provider muse --muse-auth api --config ~/.codex/agent-framework/routing.json`. A real API run requires a key; it never falls back to stored login. Default Muse keeps existing stored authentication, whose billing type the framework cannot determine. Stored-auth and explicit API quota use separate files (`muse-quota.json` and `muse-api-quota.json`), while writer protections stay shared. In API mode, Wonder Full selections use API-supported Wonder with the requested effort; results show the actual model. No automatic switch to API spending occurs. Meta may charge PAYG after credits are gone; the framework does not check balances or enforce a credit ceiling. See Meta's [authentication and billing](https://dev.meta.ai/docs/muse-code/auth), [subscriptions](https://dev.meta.ai/docs/muse-code/subscriptions), and the setup/examples in [FRAMEWORK.md](docs/FRAMEWORK.md).

This is local process, cache and claim coordination on one machine. CLI permissions and secret filtering add defense in depth; they are not a cross-process security boundary. Offline fake-CLI tests establish parser and routing behavior, while live authentication, account entitlement and provider-enforced tool capabilities require bounded signed-in validation.

## Claude Code host

`python install.py --host claude` installs the same dispatcher for a Claude Code primary: policy in `~/.claude/CLAUDE.md`, native roles in `~/.claude/agents/`, skills (including `ask-codex`) in `~/.claude/skills/`, and Claude-specific default chains from [claude/routing.overlay.json](claude/routing.overlay.json). It is separate from a Codex install and keeps its own state. See [CLAUDE_HOST.md](docs/CLAUDE_HOST.md).

## Setup and operation

Install the external CLIs and sign into the intended subscription accounts before expecting any route to run. Codex uses its ChatGPT login path; a stored API key or alternate provider configuration must not be assumed to use the subscription. Muse Power needs its interactive browser sign-in and an entitled CLI model ID; regular Wonder and Wonder Full access should be checked separately. Claude and Gemini likewise need installed, signed-in CLIs. The installer discovers executable paths but does not log in, purchase a plan, redeem credits or establish model entitlement. Jev search/review evidence is prepared by the primary/native agent and referenced in task JSON; external children do not inherit its API key. See [JEV.md](docs/JEV.md).

Copy [task-template.json](task-template.json) into the active repository's `.llm-output/` and fill its objective, explicit owned paths, acceptance criteria, checks, instructions and Jev evidence. `status --activity` is a local cache read; it does not create a provider run. `dispatch --activity` executes one ordered chain. Use `--profile` or `--provider` for an explicit choice, `--dry-run` to inspect the command, and `--state-dir` only when every cooperating task deliberately shares that alternate state. The same installed state directory must govern all workspaces using an account.

Results and redacted artifacts are saved under the task workspace's `.llm-output/agent-framework/`. A validated completion still needs the specified tests and primary acceptance. Exit 20 means confirmed or cached quota; `all_routes_unavailable` names attempted routes. For timeout or malformed terminal output, inspect `pending_path`, confirm the old writer and provider session have stopped, and only then resolve the pending record. Do not delete logs, clear quota files or launch an overlapping fallback to force progress. Disjoint file ownership may continue. The [operational guide](docs/FRAMEWORK.md) covers state recovery, orchestration child markers, review binding, and legacy command behavior.

After source changes, run `python scripts/run_tests.py -q`. This runs the offline unittest suite with temporary files under `.llm-output/test-temp`, including child-process scratch files, so restricted Windows environments do not depend on the system temporary directory. Junction tests explicitly skip when the platform denies junction creation. These tests use local fake processes. Live signed-in probes and repository CI are separate acceptance gates.
