# Framework operation

Version 12 keeps one installed `routing.json` under the Codex home. `profiles` name a provider, CLI model and effort; `activities` list profiles in priority order. Provider entries supply executable, timing and secret controls. Profiles override model and effort without mutating their provider entry. The packaged defaults cover 15 activities and all four providers; operators may edit chains and profiles. Malformed, duplicate, unknown or disabled references fail before model execution.

## Bounded task

The task file is JSON with `objective`, `acceptance_criteria`, `owned_paths`, `validation` and `instructions_files`. Writing activities require nonempty explicit `owned_paths`; a directory claim includes descendants. The optional `review.author_provider` moves that provider behind other eligible providers for independent review. Add `review.candidate`, `review.diff_path`, `review.base` and `jev.review` evidence for a stable reviewed candidate. With `workflow.require_jev_evidence=true`, implementation contracts include `jev.search` and review contracts include `jev.review`; attempted review evidence must match the saved diff SHA-256. Coverage maps identify planned, proved and unproved cases with candidate-specific evidence or limitations.

```powershell
$framework = "$HOME/.codex/agent-framework"
$runner = "$framework/scripts/provider_runner.py"
python $runner status --activity implementation --config "$framework/routing.json"
python $runner dispatch --activity implementation --workspace "C:/repo" --task-file "C:/repo/.llm-output/task.json" --config "$framework/routing.json"
python $runner dispatch --activity independent_review --workspace "C:/repo" --task-file "C:/repo/.llm-output/review-task.json" --review-reason "optional for medium; required for high/deep" --config "$framework/routing.json"
```

`--profile` pins a profile; `--provider` restricts selection to the first eligible profile on that provider. They cannot be combined. `--dry-run` makes no inference. `status --activity` reads local quota files only. `quota-set --provider openai|claude|gemini|muse --reason TEXT [--reset-at ISO_TIME]` records a user-reported account limit without contacting the provider. Never invent a reset time, redeem credits or bypass a cache with another state directory.

## Capabilities and failure handling

Planning, exploration, test design, independent/security/deep review, refactor audit and docs research are static readers. Implementation, complex/long-horizon implementation, testing, verification and documentation are writers. Verification may run checks and write generated/scratch files within its task; source edits still follow the contract. `orchestration` requires `allow_delegation: true`, holds a claim on its declared paths, and must call this dispatcher for children. Registered children may work inside that parent scope; unrelated overlapping writers cannot.

Codex runs `codex exec` with a pinned OpenAI model/effort, forced ChatGPT login, the OpenAI provider, ignored user config and an ephemeral session. Windows accepts `mxc`, `elevated` or `unelevated`. Normal activities use `providers.openai.windows_sandbox` (default `mxc`); orchestration uses `providers.openai.orchestration_windows_sandbox` (default `unelevated`). Current-host MXC blocks Python strict path resolution needed by the child dispatcher, consistent with the [reported Windows issue](https://github.com/openai/codex/issues/53045). The supported compatibility mode preserves strict canonical ownership checks; local controls proved state-root writes and denied an outside-root write. Operators can choose another supported mode for their host. Its read-only sandbox and per-run apps/agents/plugins/MCP controls restrict static roles. OpenAI children retain `CODEX_HOME` for subscription auth but discard inherited desktop IPC, policy and task-session variables; those can inject host MCP tools or reject local reads. Claude static roles expose only Read/Glob/Grep with strict MCP config. Muse static roles request a per-run `read_file` toolset and disable shell, workspace writes and web tools; this narrows file discovery compared with the other readers. First-party Muse documentation says toolset selections limit the main conversation, an offline invalid-tool control is rejected before execution, and a bounded current-host transport probe offered only `read_file`. Managed-policy conflicts remain untested. Gemini static roles require the installed `framework-reader` custom agent with only `view_file` and `grep_search`; the dispatcher validates its global file path and rejects duplicate YAML names in known global, project and plugin locations before launch. A signed-in probe selected that named agent and completed actual fixture reads; its initialization tool catalog also lists tools outside the selected agent, so that catalog is not evidence of their availability to this reader. Gemini `--mode plan` only prepends a prompt and is insufficient as a permission boundary.

A terminal quota result updates one provider-wide cache, skipping every model on that account until a known reset or bounded probe. Authentication, model, permission and transient 429 errors are distinct. The dispatcher attempts each route at most once. It advances after known terminal/setup failure and resolved writer ownership, carrying bounded prior logs/results and preserving partial files. A missing or malformed terminal, timeout or cancellation retains the pending claim; inspect and resolve it only after authoritative cessation. Disjoint claims can proceed under the shared lock. No live fallback is launched from an uncertain writer.

Review prefers a different provider from the author and reports when only the author's provider succeeds. The saved candidate and Jev diff binding remain the same across retries. Model completion alone does not establish acceptance; the primary assesses test evidence and unresolved findings. High/deep review requires `--review-reason`.

## Standalone CLI orchestration

Launch the chosen CLI agent with a task whose `activity` is `orchestration`, `allow_delegation` is true, and whose instructions give the installed runner/config paths above. The CLI agent should scope work, write child contracts under its workspace `.llm-output`, call `dispatch --activity ...` for each child, wait for result JSON and command checks, then integrate and review the candidate. It must obey nonoverlapping ownership and stop on unresolved child claims. For OpenAI orchestration, `codex exec` stays in workspace-write mode with the canonical shared state as an additional writable root and network enabled for authenticated child CLI calls. Set `providers.openai.orchestration_writable_roots` only to concrete provider cache directories that a child needs; filesystem/home roots are rejected. This is agent-directed orchestration through the shared dispatcher, not a self-operating scheduler. Plain planning does not execute that flow.

The legacy `implement` and `review` commands retain pinned Gemini/Muse and Claude behavior for compatibility. They reject `--activity` and `--profile`; use `dispatch` to avoid a write-capable activity with a legacy read-only ownership role. Legacy native fallback metadata is separate from the v12 automatic chains. Run `python -m unittest discover -s scripts -p test_*.py` after runner or installer changes. Fake CLI tests do not prove subscription entitlement or live permission behavior.

## Installation and state recovery

The default installation root is `~/.codex`; `CODEX_HOME` or `install.py --codex-home` selects another. The Gemini reader helper always lives under the actual user home at `~/.gemini/config/agents/framework-reader.md`, independent of the Codex installation root. The installer backs up files it owns before replacement, merges its marked policy block, and records hashes in `install-manifest.json`. An ordinary v12 upgrade adds missing provider/profile/activity defaults while preserving valid operator choices and quota bytes, and corrects the reader path generated by an earlier custom-root install. `--refresh-routing` is an explicit rebuild for moved executables and can discard retired custom secret-name metadata; inspect that choice before using it. The Gemini reader helper upgrades only when its installed bytes match the previous manifest hash; an operator edit or unowned collision stops installation before overwrite. Start a new Codex task to discover installed roles and skills; an already loaded host catalog does not switch models dynamically.

Use the installed `routing.json` and its sibling `state/` for every workspace. `--state-dir` is for deliberately shared alternative state or isolated offline fixtures, never to evade a cached account block. A standalone orchestrator passes its effective state directory and run ID into each child dispatch. Account files include `openai-quota.json`, `claude-quota.json`, `gemini-quota.json`, and `muse-quota.json`. DeepSeek has been removed; a leftover `deepseek-balance.json` is ignored and can be deleted. A confirmed terminal limit records observation, retry time and source evidence. A precise provider reset is used when unambiguous; otherwise `quota_probe_seconds` is only a bounded probe cooldown. Local `status` means eligible to try, not authenticated, entitled or guaranteed available.

Per-run logs, task prompt, redacted result and git evidence live under the active workspace's `.llm-output/agent-framework/`. `stdout.log` can still contain sensitive model or tool material and should be handled accordingly. Stream progress in `progress.json` and quiet-period `heartbeat.json` is diagnostic liveness, not proof of completion. The runner reads bounded stream tails, requires provider-specific terminal records, and preserves partial edits. Do not delete scratch logs to force retry.

Writers record claims under `state/workspaces/<workspace-hash>/gemini-pending/<run-id>.json`; legacy markers are still inspected. An unresolved marker blocks exact, ancestor or descendant paths, while disjoint claims can proceed. A timeout can prove the local CLI exited without proving escaped descendants or provider-backend cessation. Inspect the `pending_path` in the result and confirm the prior session stopped before marking it `resolved`; never resolve it merely because another provider is available. Orchestrators keep separate run and child-dispatch records that also block overlapping unrelated writers. An unresolved child blocks parent settlement and replacement; child registration stops accepting launches once the parent finishes. After confirming a child with no provider pending path has stopped, run `provider_runner.py resolve-orchestration --state-dir STATE --workspace WORKSPACE --run-id ID --child-id CHILD_ID --confirm-stopped --reason TEXT`. Resolve any provider pending record first. After every child is settled, use the same command without `--child-id` to confirm an uncertain parent has stopped. The records retain the reason and timestamp. If a child JSON record is corrupt, recovery fails closed: preserve its original bytes separately, confirm every child process and provider session has ceased, then reconstruct that same child's minimal valid record with `status: unresolved`, the original `parent_run_id`, workspace and owned paths, plus its `provider_pending_path` if known. Resolve the provider pending record first, then use the explicit child and parent cessation commands; never delete the corrupt record to unblock work. A completed CLI message without a child dispatch is not successful orchestration.

Legacy direct routes still use their historical fallback metadata: Gemini exhausted or unavailable leads to native Luna medium; Claude review leads to native Astra low. The activity dispatcher instead walks its configured chain, returning `all_routes_unavailable` if no route completes. Exit 0 means a provider produced a validated terminal result; it does not establish test coverage or merge approval. Exit 20 indicates cached or newly confirmed quota fallback. Other failures report setup, permission, terminal or pending state explicitly. Authentication, model failures and transient 429 responses do not poison the quota cache. Review and integration should reuse matching check evidence and a stable candidate; provider output is a handoff, not independent verification.
