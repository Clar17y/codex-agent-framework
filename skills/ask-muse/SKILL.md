---
name: ask-muse
description: Route an explicitly selected implementation task to the signed-in Muse Code CLI through the installed framework, with local quota preflight and native Luna fallback.
---

Use `{{CODEX_ROOT}}/agent-framework/scripts/provider_runner.py` with Python 3.11 or newer. Muse is opt-in for implementation; the implicit routine route remains Gemini and independent review remains Claude. Do not change the user's primary Codex model.

Muse has three explicit routing profiles, selected with `--muse-profile` (default `routine`): `routine` uses regular Wonder (`muse-wonder-1.0`) at medium effort from the base `providers.muse` entry; `complex` uses Wonder Full (`muse-wonder-full-1.0`) at medium effort; `escalation` uses Wonder Full (`muse-wonder-full-1.0`) at high effort. The `complex`/`escalation` values live under `providers.muse.profiles` and override only model/effort; executable, timing, quota and credential handling stay shared. There is no automatic retry or escalation: the primary selects `escalation` only after a previous writer is confirmed stopped and its claim resolved, passing the original contract, current diff and failed checks.

Run `python "{{CODEX_ROOT}}/agent-framework/scripts/provider_runner.py" status --provider muse --config "{{CODEX_ROOT}}/agent-framework/routing.json"` before delegation (add `--muse-profile complex` or `--muse-profile escalation` to see the selected model/effort). This reads only local state and never contacts Muse. An active `fallback_required` or `state_error` routes directly to native `implementer` on `gpt-6-luna` at medium effort; disclose the actual reason. `available_to_try` permits a CLI attempt but does not verify subscription access.

Muse must be installed and signed in with the intended subscription account through its interactive CLI/browser flow first. Set `providers.muse.model` to an official CLI model ID, or use `"cli-default"` to select the model configured in Muse itself (including a subscription model whose CLI ID is undocumented). The packaged explicit default is `muse-wonder-1.0`; it does not establish entitlement. API keys created separately may be billed pay as you go, and a stored API key can override browser sign-in. The adapter removes known key environment overrides from child processes, but it does not inspect or modify stored Muse credentials. Resolve the account in Muse before using this route.

Give the worker a compact contract with explicit non-overlapping owned files, acceptance criteria and validation commands. The worker owns investigation, implementation, testing, ordinary repairs and self-review. When `workflow.require_jev_evidence=true`, the primary/native explorer supplies `task.jev.search` evidence before a provider launch. Invoke `implement --provider muse --workspace <workspace> --task-file <contract> --config "{{CODEX_ROOT}}/agent-framework/routing.json"` for routine work, adding `--muse-profile complex` for a complex bounded task or `--muse-profile escalation` for a deliberate escalation, and wait for its terminal result. The runner uses `muse exec --json --prompt-file` in the specified workspace and keeps its sandbox active while skipping headless approval prompts. Never start a fallback writer while a Muse or Gemini claim is unresolved.

Confirmed terminal subscription exhaustion is cached in shared `state/muse-quota.json` until a known reset or bounded probe time. `quota-set --provider muse --config "{{CODEX_ROOT}}/agent-framework/routing.json" --reason "User-reported exhaustion"` records an explicit operator report; add `--reset-at` only when the time is known with a timezone. Quota, CLI/setup and other established failures fall back to native Luna medium, with the actual cause reported. A timeout or uncertain terminal retains the ownership claim until the run is confirmed stopped and the pending record is resolved. Neither a live heartbeat nor a progress event proves completion.
